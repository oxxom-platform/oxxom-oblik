# ERROR-PAGES-01 — системные страницы OXXOM OBLIK

17.11.2026 · входит в принятый SECURITY-01. Реализация подготовлена;
установка и проверка внешнего прокси фиксируются отдельно.

## Визуальное решение

[404 на компьютере](media/error-404-desktop.png) ·
[503 на телефоне](media/error-503-mobile.png)

Общая с HUB идея — короткое объяснение и понятный выход из ситуации.
Композиция Обліку самостоятельная: белая карточка, зелёный лист документа с
кодом, тонкая строка состояния и две ссылки. Используется утверждённый
графический логотип, без перерисовки букв. Светлая палитра, без анимации,
внешних шрифтов, JS, аналитики и сторонних запросов.

На мобильном карточка перестраивается вертикально. Управление доступно
клавиатурой; есть видимый фокус, заголовок и подписанная навигация.
Тексты доступны на украинском, английском, русском и чешском; язык URL
приоритетнее сохранённого выбора. Исключения и пользовательские значения
никогда не вставляются в страницу.

| Код | Смысл | Где обрабатывается |
|---|---|---|
| 400 | Запрос не принят | Django handler400 |
| 403 | Недостаточно прав; отдельный текст для CSRF | Django handler403 / CSRF_FAILURE_VIEW |
| 404 | Страница не найдена | Django handler404 |
| 429 | Пауза из-за лимита запросов | HTML middleware; собственный Nginx host |
| 500 | Не удалось завершить действие | Django handler500 без контекста БД |
| 502 | Нет корректного ответа от приложения | Собственный Nginx host |
| 503 | Временная недоступность | HTML middleware; собственный Nginx host |
| 504 | Тайм-аут ответа | HTML middleware; собственный Nginx host |

Для 500/502/503/504 нельзя обещать, что операция не выполнилась: пользователю
предлагается проверить состояние документа перед повторным сохранением или
проведением. Автоповтора POST и автообновления страницы нет.

## Протокол и безопасность

Статус остаётся 4xx/5xx, а не 200. Ошибки получают noindex/nofollow и no-store.
HTML имеет строгую CSP с хешем стиля, запрет iframe, nosniff и no-referrer.
Логотип, favicon и стили встроены: страница не зависит от статики приложения.
500 рендерится без request context processors, сессии, пользователя и запросов
к базе. Публичных маршрутов для искусственной генерации 500/503 нет.

API сохраняет JSON. Handler-ошибки и CSRF возвращают короткий машинный код;
существующие бизнес-ошибки JSON не заменяются HTML. Nginx не перехватывает
ответы приложения: собственная ошибка прокси получает HTML для страниц и JSON
для `/api/`. Retry-After задан для 429/503; точное время восстановления не обещается.

## Установка на существующий Nginx Manager

Генератор: `manage.py build_error_pages НОВАЯ_ПАПКА`. Он создаёт 32 автономных
HTML и `oblik-errors.conf`, не изменяет и не перезапускает Nginx.
Ubuntu updater складывает такой набор в защищённый каталог релиза.

1. На reverse-proxy определить **фактический контейнер Nginx Manager** и его
   существующий `/data` volume. Не угадывать имя контейнера и путь на хосте.
2. Скопировать 32 HTML в `/data/oxxom-oblik-errors` этого контейнера; файлы должны
   читаться Nginx. Не публиковать recovery-каталог целиком: он содержит журналы
   и исходные версии приложения.
3. В Advanced **только proxy host `oblik.oxxom.com.ua`** добавить содержимое
   `oblik-errors.conf`. Не менять глобальный Nginx, другие host-ы и upstream.
   Не включать `proxy_intercept_errors on` — иначе изменится API-контракт.
4. Сохранить предыдущий Advanced для отката. Выполнить `nginx -t` в фактическом
   контейнере; применять reload только после успешной проверки конфигурации.
5. В отдельном тестовом host проверить 502/503/504, методы GET/POST, JSON API,
   четыре языка и запрет прямого доступа к internal location. Не останавливать
   production-приложение ради проверки страницы.

При неожиданном результате вернуть прежний Advanced, выполнить `nginx -t` и
reload. Удаление каталога страниц до удаления include приведёт к другой ошибке.
Настройка внешнего прокси требует доступа к его актуальной конфигурации;
генерация набора не равна установке на нём.

## Проверки

- `core.test_errors`: настоящие Django handlers, CSRF, API JSON, CSP, отсутствие
  контекста БД/секретов, языки, статусы, отсутствие автоповтора операций.
- `tests/verify_error_proxy.py`: настоящий Nginx в изолированном окружении,
  статусы, языки, POST, internal locations, сохранение JSON приложения и отказ upstream.
- Изолированный Chromium: 320/390/768/1440 px × четыре языка, без горизонтального
  переполнения; логотип загружается; кнопки не меньше 48 px по высоте.
- Workflow `Security error responses`: закреплённые commit SHA действий,
  read-only token, без production secrets и deployment.
