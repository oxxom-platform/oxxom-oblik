# LANDING-01 — публічна головна OXXOM OBLIK

Реалізовано 16.11.2026 за запитом власника. Сторінка інтегрована в наявний
локальний Django-застосунок, окремий сайт чи хостинг не створювалися.

## Маршрути

- `/` — публічний лендинг (HTTP 200), замінює перенаправлення на `/app/`.
- `/login/` — наявний вхід із паролем і 2FA.
- `/app/` — захищений робочий простір. Гість переходить до входу.
- `/assets/landing/landing.css` та `/assets/landing/landing.js` — дозволені
  локальні ресурси. Інші імена за цим префіксом дають 404.

## Вміст та поведінка

Світла сторінка українською з оригінальним SVG-логотипом: перший екран,
приклад робочого простору, можливості документів/складу/грошей/звітів,
чотири кроки робочого процесу, ролі команди, FAQ та кнопки входу.
Цифри прикладу явно позначені як ілюстративні; дані організацій не
запитуються й не відображаються. Немає вигаданих відгуків, клієнтів,
тарифів, заявок чи відкритої самореєстрації.

FAQ пояснює поточний етап MVP, внутрішній облік платежів без ПРРО,
можливості CSV та друку. Приклад інтерфейсу — ілюстрація процесу,
не інтерактивний доступ до даних або демонстраційної організації.

Навігація за розділами й розкриття FAQ працюють без JavaScript.
Мобільне меню реалізовано через native details; скрипт закриває його
після переходу, при натисканні зовні та Escape з поверненням фокуса.
Додано видимий фокус, пропуск до основного вмісту, reduced-motion,
заголовок сторінки, description та Open Graph без вигаданого домену.
Зовнішніх шрифтів, аналітики й сторонніх скриптів немає.

Головна не залежить від доступності БД. Права, MFA, документи та дані
наявних модулів не змінюються. Схему БД не змінено; міграцій немає.

## Перевірки

- 63 тести `core` і `accounts` на окремій PostgreSQL-БД: успішно,
  без пропусків. Перевірка міграцій — без змін.
- Публічний рендер із забороненим доступом до БД, внутрішні посилання,
  відсутність організаційного контексту, закритий список ресурсів.
- Реальний Chrome: ширини 320, 390, 768, 1024, 1440 px без горизонтального
  переповнення; оригінальний логотип завантажується, меню/FAQ працюють.
- Для гостя `/app/` переходить на `/login/`; помилок JavaScript немає.

Браузерна перевірка використовувала окремий тимчасовий сервер із порожньою
БД у пам’яті; робочі записи користувача не змінювалися. Скриншоти слугували
лише внутрішньою перевіркою візуального вигляду.

## Як відкрити

З кореня проєкту перезапустити `sh scripts/start-core.sh`, потім відкрити
http://127.0.0.1:4180/. Якщо старий редирект залишився у вкладці, вручну
перейти на цю адресу. Кабінет залишається за `/app/`.
