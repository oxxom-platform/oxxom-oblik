# Довідники REF-01

15 листопада 2026 року. Локальний блок етапу 4; Ubuntu VM ще не створено.

## Запуск і ручне приймання

Після Ctrl+C у терміналі вебсервера виконайте з кореня проекту:

```sh
sh scripts/start-core.sh
```

Скрипт застосує catalog.0001 і запустить accounts, core та catalog тести.
Відкрийте http://127.0.0.1:4180/catalog/ або «Відкрити довідники» в кабінеті.
Потрібна завершена MFA-сесія. Організація і довідник вибираються зі списків.

Для нових і наявних організацій з повністю порожнім довідником міграція catalog.0002 додає «Штука» / «шт», «Година» / «год», «Послуга» / «посл». Наявні налаштування та архівні одиниці не змінюються. Додаткові одиниці можна створити в довіднику. Потім створіть
товар із ціною 100.00 та послугу 1500.00, вибравши одиниці зі списку. Додайте
контрагента та склад. Перевірте збереження після оновлення сторінки,
редагування, пошук і архів. Для перевірки конфлікту відкрийте редагування
одного запису у двох вкладках: після першого збереження друга має отримати
409, зберегти введену форму і запропонувати оновити список. Для повторного
редагування потрібно заново вибрати запис зі списку, щоб завантажити його
актуальну версію.

## Реалізовано

- Товари/послуги: назва, тип, артикул, одиниця зі списку, ціна Decimal UAH.
- Контрагенти: назва/ПІБ, тип, код, email, телефон, адреса, реквізити, примітка.
- Склади: назва. Одиниці виміру: назва та позначення.
- Створення, редагування, архівація і відновлення без HTTP-видалення.
- Пошук за назвою, фільтр активні/архівні/всі, пагінація 50 записів.
- UUID, організаційна ізоляція, перевірка прав, MFA і CSRF для змін.
- Версія запису: застаріле редагування/архівація відхиляється без перезапису.
- Атомарний CatalogEvent з організацією, діячем, UUID запису, дією та версією.
  Персональні поля контрагента та значення реквізитів у події не копіюються.

Активні записи показуються за замовчуванням. Чужу або архівну одиницю
не можна призначити новому товару. Наявний товар може зберегти раніше
призначену одиницю навіть після її архівації. Зв’язки з одиницями захищені
PROTECT; архівація не видаляє наявні посилання.

| Роль | Читання | Зміни |
|---|---|---|
| Власник, бухгалтер | Усі довідники | Усі довідники |
| Менеджер | Усі довідники | Контрагенти |
| Комірник | Товари без ціни, одиниці, склади | Склади |
| Спостерігач | Усі довідники | Немає |

Це конкретизація прав REF-01; складські рухи та фінансові звіти не відкриваються.
Перевірки виконуються для кожного запиту. Перед зміною блокується рядок
організації, що узгоджується з блокуванням при відкликанні членства, а потім
рядок довідника; перевірка версії і запис події відбуваються в одній транзакції.

## API

Базовий шлях: /api/v1/organizations/{organization_uuid}/catalog/{kind},
де kind — units, products, counterparties або warehouses.

- GET базового шляху: q, status (active/archived/all), page.
- POST /add: поля картки; організацію/статус/версію визначає сервер.
- POST /{uuid}: поля картки та поточна version.
- POST /{uuid}/state: version та is_active=true/false.

Права інтерфейсу: GET /api/v1/organizations/{uuid}/catalog-permissions.
Одиниці, організація, типи та ролі обираються зі списків. Назви карток
вводяться при веденні довідника. Введення довільної позиції в документі
не реалізовується: документи наступного етапу використовуватимуть ці UUID.

## Перевірки та межі

73 тести у загальному наборі: 71 пройшов на тимчасовій SQLite, 2 конкурентні
тести AUTH/ACCESS пропущено, бо потребують PostgreSQL. Новий блок має 21
тестів: права ролей і відсутність ціни для комірника, чужі UUID/одиниці,
архівні одиниці, валідація цін, версії, пошук/пагінація, MFA, CSRF і відкат
при помилці журналу. Перевірено узгодженість міграцій, шаблон через Django
клієнт і синтаксис JS через node --check. Ручне браузерне приймання і запуск
на PostgreSQL ще потрібні на Mac. Робочу конфігурацію БД не змінено.

Документів, проведень, залишків, імпорту та експорту ще немає. Обмеження
БД не замінюють перевірку зв’язку товар–одиниця за організацією: усі записи
через API проходять перевірку ModelForm. Прямий SQL/ORM обхід API не є
підтримуваним імпортом; майбутня команда імпорту має використовувати ті самі
правила. Міграція додає тільки таблиці; для відкоту коду їх зберігають.
Зворотна міграція видаляє довідники та журнал і не виконується автоматично.

## Виправлення порожнього списку одиниць

catalog.0002 заповнює тільки організації без жодної одиниці. Новий власник отримує ті самі три стандартні одиниці в транзакції створення організації. Повторне виконання не створює дублікатів. Якщо всі одиниці архівовані, форма показує пояснення й блокує збереження товару/послуги до вибору одиниці. Зворотна data-міграція не видаляє вже використані одиниці.
