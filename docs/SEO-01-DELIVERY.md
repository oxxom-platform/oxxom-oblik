# SEO-01 — результат и установка

17.11.2026. Код подготовлен для существующего Ubuntu-сервера. Установка на
production и проверка внешнего HTTPS из среды разработки не выполнялись.

## Что входит

* Четыре главные страницы: `/` (uk), `/en/`, `/ru/`, `/cs/` с переводом HTML
  на сервере, самостоятельными title/description, canonical и взаимными hreflang.
* URL определяет язык публичной страницы; выбранный язык сохраняется для
  кабинета. Действующая MFA-сессия ведёт из `/login/` в `/app/`.
* Sitemap с четырьмя публичными URL, robots.txt, noindex для входа, кабинета,
  печати, API и ошибок. Доступ к данным по-прежнему требует авторизации.
* Open Graph/Twitter и четыре публичных PNG 1200×630. JSON-LD описывает только
  организацию и сайт; нет выдуманных предложений, цен или отзывов.
* Оптимизированный PNG исходного логотипа 38 KiB вместо загрузки SVG около
  972 KiB на лендинге; начертание не менялось. Полный словарь кабинета на
  публичной странице больше не загружается. CSS/JS имеют версии по содержимому.
* Единый favicon: исходная зелёная плашка OBLIK, без OXXOM, на прозрачном фоне.
  PNG 256×256, Apple Touch 180×180, ICO 16/32/48/256; общий шаблон применяется
  на лендингах, входе/MFA, в кабинете и печати. Корневой `/favicon.ico` также доступен.
* Компактный header, поднятый первый экран и отсутствие точек в заголовках
  сохранены. FAQ и описание доступа отражают текущий Ubuntu MVP.

## Обновление Ubuntu

Установленная копия — архив GitHub, а не Git checkout. `git pull` не применяется.
Запускать `deploy/ubuntu/update-seo.sh FULL_REVIEWED_COMMIT_SHA` на Ubuntu
от administrator. Использовать полный SHA проверенного коммита, не имя ветки.
Скрипт скачивает архив закрытого репозитория через GitHub CLI. Если сервер
ещё не авторизован, CLI предложит вход через браузер с одноразовым кодом.

`apply-seo-update.py` проверяет manifest и контрольные суммы только 29 разрешённых
файлов backend. Неизвестные правки сервера останавливают обновление до записи.
Допустимы исходная версия GitHub и известные ручные исправления заголовков,
отступа и сохранения MFA-сессии. Конфигурация, БД, systemd, прокси, миграционные
материалы и настройки Windows-бэкапа не заменяются.

Перед остановкой сервиса кандидат проверяется отдельно без соединения с БД,
затем запускается существующий `first-backup.py` как отдельная программа.
Нужны доступная зашифрованная Windows-шара и уже созданные пароли restic.
При ошибке подготовки сервис продолжает работать. Перед записью исходники
повторно проверяются; предыдущие файлы и журнал сохраняются с закрытыми правами
в `/srv/oxxom-oblik/update-backups/seo-*`.

После установки проверяются loopback health, четыре языка, sitemap/robots,
favicon и защита приватных маршрутов. Если запись или запуск не прошли,
возвращаются прежние файлы и запускается прежний сервис. Миграций БД нет.
Обновление требует короткой остановки приложения. Внешний Nginx остаётся прежним.

После успешного запуска отдельно проверить публичный HTTPS на четырёх языках,
реальный вход владельца, favicon (может потребоваться обновление кэша вкладки),
robots/sitemap и noindex через внешний прокси. Затем подключить Search Console,
отправить sitemap и выполнить лабораторные замеры. Новые тематические страницы,
аналитика и поисковый контент относятся к последующим SEO-02/03.
