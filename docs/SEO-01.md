# SEO-01 — поисковая оптимизация OXXOM OBLIK

Версия 1.1 · 17.11.2026 · статус: ТЗ принято; SEO-01 реализован в исходниках,
проверка и установка на Ubuntu описаны в SEO-01-DELIVERY.md. SEO-02/03 ещё не внедрены.

Проект: https://oblik.oxxom.com.ua/. Стек: Django, Ubuntu, существующий внешний
Nginx Manager. Документ относится к публичному сайту Обліку. Изменения сайтов
HUB и основного бренда, платная реклама и разработка новых учётных модулей
в этот блок не входят.

## 1. Цель и границы

Сделать публичный сайт доступным для поисковых систем, правильно представить
четыре языка, создать страницы под реальные задачи покупателей и измерять
органические переходы и обращения. Позиции, сроки индексации и попадание
в ответы поисковых AI-систем не являются гарантированным результатом.

Рабочая гипотеза: основной рынок — Украина; языки — украинский, английский,
русский и чешский. Чехоязычная версия описывает возможности текущего продукта,
не обещая соответствие чешскому бухгалтерскому и налоговому законодательству.
Семантика, конкуренты и спрос по странам уточняются перед подготовкой новых
посадочных страниц. Частотности и целевой прирост трафика пока не измерены.

Публично описывать только реализованные функции: товары и услуги, справочники,
документы продаж, поступления, складские движения, внутренний учёт оплат,
отчёты, CSV-импорт, роли и MFA. Не заявлять уже готовыми ПРРО, банковские
интеграции, M.E.Doc, расчёт НДС, полный бухгалтерский учёт или платные подписки.

## 2. Исходное состояние и ограничения аудита

Проверены доступные исходники проекта. Прямое чтение публичного домена
из среды аудита не удалось; это не доказательство недоступности сайта
для посетителей или Google. Фактические HTTP-ответы, robots/sitemap на прокси,
индексация, Core Web Vitals и данные Search Console требуют отдельной проверки.

| Наблюдение по исходникам | Задача |
|---|---|
| Есть title, description, часть Open Graph и один H1 | Уточнить семантику и локализовать метаданные |
| В шаблоне нет canonical, hreflang, JSON-LD, og:url, og:image и Twitter Card | Добавить единый SEO-контракт публичных страниц |
| Основной HTML лендинга украинский, переводы меняются JS на том же URL | Ввести отдельные серверные языковые страницы |
| Content-Language определяется cookie, включая HTML лендинга | Для публичных страниц определять язык по URL |
| В доступной конфигурации URL нет robots.txt и sitemap.xml | Добавить и проверить через фактический внешний прокси |
| Публичный лендинг подключает общий translations.js, около 225.3 KiB без сжатия | Выделить небольшой публичный словарь/данные демонстрации |
| SVG логотипа около 971.5 KiB, содержит растровые данные | Оптимизировать ресурс, сохранив точное начертание |
| «Спробувати демо» ведёт на /login/, публичный коммерческий контакт ещё не задан | Привести CTA и описание доступа в соответствие со сценарием |
| FAQ и footer ещё описывают локальный этап и будущий перенос Ubuntu | Обновить статус продукта по подтверждённым фактам |

Размеры выше — размеры файлов, не измерение сетевого трафика после сжатия.
Фактическая автоматизация бэкапов пока не принята: не обещать ежедневное
автоматическое копирование до завершения соответствующего эксплуатационного блока.

## 3. SEO-01A / P0 — URL и языки

Главная украинская версия остаётся на текущем URL. Отдельные версии:

| Язык | URL главной | html lang / hreflang |
|---|---|---|
| Украинский | https://oblik.oxxom.com.ua/ | uk |
| Английский | https://oblik.oxxom.com.ua/en/ | en |
| Русский | https://oblik.oxxom.com.ua/ru/ | ru |
| Чешский | https://oblik.oxxom.com.ua/cs/ | cs |

Для каждой страницы:

1. Основной текст, H1, title, description и SEO-теги приходят в исходном HTML
   на языке URL, без зависимости от JS, cookie или localStorage.
2. Content-Language и html lang соответствуют URL. Прямой запрос /en/ с русской
   cookie возвращает английскую страницу. Устаревший язык в localStorage не
   переводит её повторно после загрузки JS; настройки приводятся к языку URL.
   Без JS основной контент доступен.
3. Canonical — абсолютный HTTPS URL этой версии, без UTM и служебных параметров.
   Чешская и английская страницы не канонизируются на украинскую.
4. В head — взаимные hreflang-ссылки на себя и все опубликованные переводы.
   x-default ведёт на украинский вариант соответствующей страницы.
5. Использовать коды uk и cs; подписи UA и CZ могут оставаться в интерфейсе.
6. Переключатель ведёт обычными ссылками на языковые URL. Выбранный язык
   сохраняется в существующую настройку и далее применяется в кабинете.
7. Не перенаправлять посетителей принудительно по IP или языку браузера.
   Не создавать фиктивные переводы и hreflang на несуществующие страницы.
8. Неизвестные маршруты/локали возвращают настоящий 404. Правило завершающего
   слеша и регистра URL применяется к публичным страницам, не меняет API.

Проверки: четыре страницы доступны анонимно с 200; исходный HTML корректен
при выключенном JS и противоречащих языковых cookie/localStorage; переключение языка
не сбрасывает действующую MFA-сессию и не возвращает повторный вход.

## 4. SEO-01B / P0 — индексация и приватность

Ввести явный реестр публичных индексируемых страниц. Sitemap генерируется
из этого реестра, а не из списка всех Django URL.

* /robots.txt: 200, text/plain; разрешены публичные страницы и необходимые
  CSS/JS/изображения, указана абсолютная ссылка на sitemap.xml.
* /sitemap.xml: 200, корректный XML UTF-8; только опубликованные canonical URL
  со статусом 200. На первом этапе — четыре главные страницы.
* lastmod отражает изменение содержимого страницы. Не подменять его временем
  каждого запроса или ежедневного запуска сайта.
* /login/ — noindex. Кабинет, API, документы, печатные формы, экспорты и
  служебные ответы получают X-Robots-Tag: noindex и остаются защищены
  действующей авторизацией и проверкой организации.
* Не закрывать /login/ в robots.txt одновременно с ожиданием, что бот прочтёт
  его noindex. Сам по себе Disallow не является запретом индексации URL.
* Для уже обнаруженных приватных URL применять доступный боту noindex либо
  корректный 401/403/404; не считать robots.txt защитой пользовательских данных.
* Приватные ссылки, UUID документов, имена организаций, email пользователей,
  MFA-коды и финансовые значения не попадают в sitemap, JSON-LD и OG.
* Не подменять закрытые страницы публичной главной со статусом 200.
* Публичные изображения бренда/OG не закрываются политикой приватных файлов.

Приёмка: sitemap не содержит login, app, api, print, export или query-параметры;
анонимный клиент не получает бизнес-данные; noindex проверен в реальном HTTP-ответе.

## 5. SEO-01C / P0 — метаданные и семантика главной

Реализовать централизованные SEO-данные для каждой пары «страница + язык»:
title, description, H1, canonical, alternate URLs, OG и JSON-LD. Все значения
экранируются; публичный origin задаётся явно и не строится из произвольного Host.

Черновик для украинской главной:

* Title: OXXOM OBLIK — облік товарів, складу та оплат
* Description: Облік товарів і послуг, складські залишки, документи та оплати
  в одному сервісі. OXXOM OBLIK допомагає впорядкувати щоденні операції бізнесу.
* H1: сохранить «Облік, який працює на вас»; конкретное назначение продукта
  раскрыть в подзаголовке первого экрана.

Для остальных языков подготовить самостоятельные корректные тексты, проверить
терминологию чешской версии. Не размножать ключевые слова в заголовках.
Один H1 — правило шаблона проекта; далее логичная иерархия H2/H3.
Сохранить согласованное отсутствие точек на концах заголовков.

Open Graph: og:type, og:title, og:description, og:url, og:locale, og:image,
размеры и alt изображения. Twitter Card — summary_large_image с соответствующими
метаданными. Подготовить публичное брендированное PNG/JPEG-превью 1200×630
без данных пользователей. Изображение возвращается без авторизации.

## 6. SEO-01D / P0 — скорость и устойчивость интерфейса

* Единый favicon на всём сайте: только исходная зелёная плашка с белым OBLIK,
  без OXXOM и белой рамки, прозрачное окружение. Подключить на четырёх лендингах,
  входе/MFA, всех страницах кабинета и печати. Поддержать `/favicon.ico`, PNG
  и Apple Touch Icon; проверить ответ 200 без авторизации и отсутствие старого
  полного логотипа в `rel="icon"`. Основной логотип в шапке не менять.
* Зафиксировать исходные замеры мобильной и десктопной версии.
* Оптимизировать тяжёлый логотип: исходный вектор при наличии либо оптимизированный
  прозрачный растр нужного разрешения. Сохранить фирменную надпись OXXOM,
  чёрный цвет, зелёный OBLIK и пропорции; не заменять надпись обычным шрифтом.
* На лендинге не загружать весь словарь кабинета. Публичная страница получает
  локализованный HTML и минимальные данные для интерактивной демонстрации.
* Убрать блокирующую загрузку необязательных JS; сохранить порядок инициализации
  языковых настроек, меню и демонстрации.
* Для изображений задать размеры; содержимое ниже первого экрана загружать
  отложенно. Не применять lazy-loading к изображению, если оно определяет LCP.
* Использовать версии ресурсов по содержимому, долгий cache только для таких
  версий; gzip/Brotli проверять на существующем внешнем прокси.
* Сохранить компактный закреплённый header, небольшой верхний отступ, светлую
  тему и согласованную плавную анимацию чисел. Не добавлять постоянные эффекты.
* Не допускать горизонтального скролла и перекрытия якорных заголовков хедером
  на ширинах 320, 390, 768, 1024, 1440 и 1920 px во всех четырёх языках.

Целевые полевые значения p75: LCP ≤2.5 с, INP ≤200 мс, CLS ≤0.1.
До накопления полевых данных выполнить три лабораторных мобильных замера
с одинаковыми условиями и сохранить медиану. Ориентиры проекта: Lighthouse
Performance ≥90 и SEO ≥95. Лабораторные результаты не выдавать за полевой INP.
Недостаток данных CrUX отмечать как «не измерено», а не «пройдено».

## 7. SEO-02 / P1 — посадочные страницы и содержание

Сначала собрать семантическое ядро по регионам/языкам, отделить информационные
и коммерческие намерения и сопоставить каждый кластер одной основной странице.
Ниже стартовая структура, а не подтверждённые частотности запросов.

| Украинский URL | Назначение и стартовый кластер |
|---|---|
| /features/inventory/ | Складський облік, залишки, надходження, переміщення |
| /features/sales-documents/ | Облік реалізацій, рахунки, накладні, акти |
| /features/payments/ | Облік оплат і заборгованості; внутренний учёт денег |
| /features/reports/ | Звіти продажів, складу й управлінські показники |
| /features/import/ | Імпорт довідників із CSV |
| /security/ | Роли, MFA, разграничение доступа и подтверждённые меры защиты |
| /pricing/ | Утверждённые условия доступа и реальный способ запросить предложение |
| /contacts/ | Подтверждённый публичный контакт для коммерческого обращения |

Переводы получают префиксы /en/, /ru/, /cs/. Публиковать только законченные
локализации; sitemap и hreflang включают фактически доступные страницы.

Страница функции содержит назначение, пошаговый сценарий, настоящие возможности
и ограничения, иллюстрацию на синтетических данных, FAQ и понятный следующий шаг.
Объём определяется задачей пользователя, не обязательным количеством слов.
Внутренние ссылки — обычные a href, с осмысленными названиями и без тупиков.

Скорректировать текущие тексты о «локальном MVP» и будущем переносе: Ubuntu
и ручное проверенное восстановление уже подтверждены; бухгалтерское принятие,
автоматические бэкапы и коммерческие условия описывать по их реальному статусу.
Не публиковать демонстрационные обороты как результаты клиентов.

Кнопка «Спробувати демо» сейчас ведёт на вход. Требуется честно описать текущий
сценарий и дать посетителю без аккаунта публичный способ запросить доступ.
Саморегистрация и публичный демо-tenant не добавляются автоматически этим ТЗ.
Контакт берётся отдельно как публичный; внутренние адреса для технических
уведомлений не становятся контактами лендинга по умолчанию.

## 8. SEO-02B / P1 — структурированные данные

На главной — фактические Organization и WebSite с корректными URL/логотипом.
Единую идентичность издателя OXXOM согласовать с основным брендом; не выдумывать
юридическое лицо, адрес, телефон, сертификаты, отзывы или оценки.

WebApplication/SoftwareApplication добавлять по реальному описанию продукта.
Offers/цены — только после утверждения коммерческих условий; не ставить price=0
ради прохождения проверки. Schema.org-валидность и право на конкретный Google
rich result — разные критерии. Не требовать rich result при отсутствии
необходимых реальных данных и не обещать его появление.

На вложенных публичных страницах — BreadcrumbList с реальной навигацией.
Разметка соответствует видимому содержимому и не содержит пользовательских данных.
Проверки: Schema.org validator; Rich Results Test для применимых типов.

## 9. SEO-03 / P1–P2 — измерение и развитие

1. Подтвердить сайт в Google Search Console, подать sitemap и проверить четыре
   главные через URL Inspection. DNS-доступ/права предоставляются владельцем.
2. Зафиксировать исходные показы, клики, CTR, страны, языки и индексируемые страницы.
3. Подключить согласованный счётчик только на публичном сайте с учётом правил
   согласия пользователя. Кабинет не получает сторонние маркетинговые трекеры.
4. События: выбор языка, переход на страницу функции, взаимодействие с демо,
   клик запроса доступа и клик входа. Клик «Увійти» не считать новой заявкой.
5. Подтверждённые обращения считать отдельно после появления реального канала
   связи/формы. В аналитику не отправлять email, имена, MFA, суммы, содержимое
   документов и приватные параметры URL.
6. Через 28 и 56 дней пересматривать индексацию, запросы, страницы и конверсии;
   устранять дубли, ошибки и несоответствие поисковому намерению.
7. После первых посадочных подготовить практические материалы: начальные остатки,
   CSV-импорт, проведение и сторно, привязка оплаты, проверка складских движений.
   Указывать автора/ответственного и дату содержательного обновления.
8. Для AI-поиска — ясные описания функций, проверяемые факты, актуальные ответы
   и доступный текст. Отдельных обещаний попадания в AI-ответы не давать.

## 10. Порядок внедрения и доказательства приёмки

| Релиз | Состав | Проверяемый результат |
|---|---|---|
| SEO-01 | Четыре SSR-главные, метаданные, canonical/hreflang, robots, sitemap, noindex, базовая оптимизация | Технические проверки и протокол ответов через HTTPS |
| SEO-02 | Семантика, тематические страницы, честные CTA/контакты, структурированные данные | Уникальные опубликованные страницы и корректная разметка |
| SEO-03 | Search Console, аналитика, измерения скорости и контентный цикл | Собранный baseline и отчёт по реальным данным |

Для SEO-01 автоматизировать проверки четырёх языков, HTML без JS, противоречащих
cookie, canonical/alternate и sitemap. Включить регрессионные проверки приватности,
MFA-сессии, возврата через /login/, языка кабинета и недоступности чужой организации.

Приёмочный протокол содержит URL, ожидаемый/фактический HTTP-статус, заголовки,
метаданные, версии кода, результаты мобильных замеров и статус внешних проверок.
Различать «код проверен», «доступно боту», «подано в Search Console» и «реально
проиндексировано»: индексация не гарантируется сроком выполнения релиза.

Установка — на существующую Ubuntu через один подготовленный релиз и серверную
команду, с резервной копией и откатом файлов. Схему внешнего Nginx Manager,
доверие к прокси, Secure cookies и действующую авторизацию сохранить.
Не менять секреты, базу, домены и службы HUB. Редиректы и сжатие проверять
через публичный HTTPS-домен; локальная проверка backend не заменяет их.
