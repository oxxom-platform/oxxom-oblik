# UX-AUTH-03 — спокійна головна та вхід із QR / автоматичним TOTP

16.11.2026. Власник попросив залишити тільки плавні цифри, тимчасово вести
кнопку демо до особистого входу, замінити текст ключа 2FA на QR і перевіряти
код без обов’язкового натискання кнопки. Додатково виправлено з’єднання
кришки та основи ноутбука у hero.

## Головна

Автоперемикання станів, fade екранів, плаваючі плашки та scroll-reveal
прибрані. Геометрія, графіки та блоки не анімуються. Єдина анімація —
плавна зміна чисел до 1000 мс; при reduced motion вона миттєва.
Розділи залишилися доступними для ручного вибору без приховування екранів.
Плашки мають сталу ширину, числа — табличні цифри, щоб текст не зсував рамки.

У ноутбука одна трапецієподібна основа без окремої від’єднаної передньої
смужки; шарнір перекриває нижню кромку кришки. Мобільні маски дисплеїв
та оригінальний логотип збережено.

Усі три «Спробувати демо» ведуть до `/login/`, як тимчасово попросив власник.
На сторінці пояснено, що це звичайний особистий вхід; окремого демопростору
ще немає. Після входу працюють чинні права власної організації.

## QR

Під час першого підключення `POST /api/v1/auth/setup` додає `qr_code` — SVG
data URI з TOTP provisioning URI. Зображення генерує локальна бібліотека
`qrcode==8.2`, без зовнішніх QR-сервісів, URL із секретом або нових файлів
на сервері. UI показує QR замість рядка секрету. Існуючі поля API `secret`
та `uri` збережено для сумісності; вони доступні лише після парольного етапу
для непідтвердженого пристрою. Відповіді setup не кешуються.

QR стирається з DOM після успіху або залишення сторінки. Повторний setup
під час того самого підключення показує той самий пристрій, без зміни ключа.
Наявні підтверджені пристрої не скидаються та не розкриваються через setup.
Міграцій не потрібно.

## Автоматичний код

- Шість цифр запускають перевірку через 180 мс; вставлення й autofill
  підтримуються. Є підказка про автоматичний вхід.
- Паралельний submit блокується, однакові автоматичні події не повторюють
  запит. Невірний код лишає користувача на формі з помилкою.
- Після правильного коду наявного пристрою — відразу `/app/`.
- Під час першого підключення авторизація також відбувається автоматично,
  але показуються 10 одноразових резервних кодів перед переходом у кабінет.
  Вони не губляться через негайне перенаправлення і не пишуться в browser storage.
- Для резервного коду є окремий режим; вставлення 16 символів обирає його
  автоматично, не надсилаючи перші шість цифр як помилковий TOTP.
- Кнопка підтвердження збережена для повторної ручної спроби після проблем
  мережі, але для правильного повного коду натискання не потрібне.
- CSRF, п’ять невдалих спроб, строк challenge, одноразовість TOTP/recovery,
  перевірка пароля й блокування акаунта залишаються на сервері.
- `/login/?security=1` відкриває існуючі дії безпеки після повторної перевірки;
  посилання «Безпека та резервні коди» веде сюди.

## Перевірка

245 тестів на окремій PostgreSQL-БД успішно, без пропусків. Перевірено QR,
його недоступність без challenge та для підтвердженого пристрою, стабільність
повторного setup, MFA/CSRF/replay/throttle й регресії інших модулів.

У справжньому Chrome на тимчасовій синтетичній БД перевірені звичайний
автоматичний вхід, QR-підключення, одноразове надсилання, збереження десяти
резервних кодів та автоматичний вхід через вставлений recovery code.
QR незалежно декодований браузерним BarcodeDetector: акаунт, issuer і secret
збігаються з тестовою конфігурацією. Секрети користувача не використовувалися.

Вимірювання головної під час count-up: 61 різне проміжне значення цифр,
нульовий зсув координат/розмірів перевірених пристроїв і плашок,
непрозорість екрана весь час 1. Ширини 360–1920 px перевірені на відсутність
переповнення та активні маски дисплеїв. Деталі — UX-AUTH-03-verification.txt.

Офіційний опис QR-рендерера: https://pypi.org/project/qrcode/8.2/.

## Запуск

Перезапустити `sh scripts/start-core.sh`: скрипт встановить нову закріплену
залежність. Нових міграцій немає. Головна — http://127.0.0.1:4180/,
вхід — http://127.0.0.1:4180/login/.
