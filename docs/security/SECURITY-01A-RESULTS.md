# SECURITY-01A — первый пакет исправлений

17.11.2026 · выполнение принятого [SECURITY-01](../SECURITY-01.md).
Это результат ограниченного этапа, не сертификат соответствия ASVS и не
завершённый аудит production.

## Выполнено в исходниках

**F-01: общий лимит входа за reverse-proxy.** Клиентский адрес определяется
только за точным TCP peer из `OXXOM_PROXY_IP`. По контракту одного Nginx Manager
hop используется последний адрес X-Forwarded-For; он сверяется с X-Real-IP,
который NPM перезаписывает. Заголовки прямого недоверенного клиента игнорируются.
Некорректная/отсутствующая metadata доверенного peer отклоняет auth-запрос.
HTTPS-схема и REMOTE_ADDR глобально не переписываются. Этот контракт требует
повторной оценки при добавлении CDN или второго proxy hop.

Сохраняются account/client ограничения: пять ошибок за 15 минут. Новый namespace
клиентских ключей исключает применение старого общего счётчика прокси. Account
счётчики сохраняются. Блокированный клиент проверяется до создания новой строки
произвольного аккаунта. Это не заменяет edge-rate-limiting и политику очистки
старых счётчиков — они остаются в общем ТЗ.

Добавлены [страницы ошибок](../ERROR-PAGES-01.md), API-aware CSRF response,
ограниченный read-only сборщик фактической конфигурации Ubuntu и guarded updater.

## Выпуск на Ubuntu

`deploy/ubuntu/update-security.sh ПОЛНЫЙ_SHA` скачивает только закреплённый
релиз. Installer проверяет 11 явно разрешённых файлов и SHA256, baseline четырёх
существующих файлов из установленного SEO-релиза и работоспособность приложения.
Неизвестная серверная правка останавливает обновление до записи.

Сохраняются оригиналы, выполняются Django check, генерация proxy-страниц,
перезапуск только `oxxom-oblik`, health/ready, четыре лендинга, login и 404 HTML/JSON.
При ошибке возвращаются оригиналы и удаляются новые файлы; приложение
перезапускается и проверяется после отката. Environment, ключи, зависимости,
миграции и записи сессий updater не меняет. Откат в середине внезапного отключения
VM требует recovery-файлов; это не транзакционная замена всего filesystem.

Favicon-02 не включён повторно: этот пакет работает с обоими вариантами favicon
и не подменяет уже установленные brand assets. Статические proxy-страницы
используют утверждённый зелёный PNG внутри HTML.

После установки выполнить выведенную команду `collect-security.py`. Она выводит
только allowlisted настройки, flags роли БД, версии шести пакетов, статусы
hardening, режимы двух private files, наличие backup receipts и таймеры Обліку.
Пароли, MFA/SMTP secrets, session cookie, DSN, пользовательские записи и полные
unit/env-файлы не выводятся. Сборщик не исправляет настройки и не делает бэкап.

## Остаётся по SECURITY-01

Фактическая матрица ASVS применимости, полный endpoint/field coverage между
организациями, dependency advisory scan и transitive lock, политика браузера
для всего приложения, реальные сетевые ACL/SSH/права, GitHub release chain,
автоматическое расписание и проверенные email-уведомления бэкапа, независимая
immutable/offline копия и повторная проверка на production. Пройденные
функциональные тесты не подменяют эти доказательства.

Git metadata-проверка staged list остановилась по тайм-ауту; она не объявлена
успешной. Дополнительно проверены точные опубликованные blobs 23 исходных
файлов пакета: соответствие содержимому, отсутствие private paths, известных
локальных credentials и private-key headers. Полная история Git и неизвестные
исторические credentials этой проверкой не покрываются.
